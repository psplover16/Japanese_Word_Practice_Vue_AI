unitTest 維護與測試及使用
目前專案的 npm test 就等於 npm run test:unit  (package.json)  把資料夾內的 tests/unit 和 tests/component 一起跑完

npm test  一次確認目前 unit/component 測試有沒有壞
npx vitest  開發中持續 watch，改完檔案會重跑，最適合「真正拿來用」。
npx vitest run tests/unit/usePracticeSession.spec.ts  只跑單一測試檔，修 bug 時最快。
npx vitest -t "route ownership"  只跑某個案例。
npm run test:ci  本機完整模擬 CI，會跑 lint、typecheck、unit、build、e2e，定義在 package.json (line 15)。 要 push 前跑一次

tests/unit 放純邏輯測試，例如工具函式、composable 狀態流轉。 改 utils 或 composables 時，同步更新
tests/component 放 Vue 元件行為測試，像 route 對應顯示什麼 panel。可參考 RouteOwnership.spec.ts (line 7)。 改畫面條件渲染、互動或 provider/inject 時，同步更新
tests/e2e 放完整使用流程，不要把 e2e 的責任塞進 unit test。

DOM 選取盡量用穩定 selector，例如現在已有的 data-testid 做法。

Vitest 測試執行工具(一種常見套件)，會抓 *.test.ts 以及 *.spec.ts 當作測試檔
Vitest 預設是在 Node.js 環境跑。但 Node.js 本身沒有真的瀏覽器畫面，也沒有完整的 DOM。jsdom 就是一個「用 JavaScript 模擬瀏覽器 DOM 的環境」。

CI 自動品管 / 自動驗收：一 push 或開 PR，系統自動幫你檢查程式有沒有壞，先擋住有問題的程式碼不要混進主分支
CD 持續部署 / 持續交付：當程式通過驗證後，自動把它部署到某個環境，讓使用者或測試人員真的可以打開網站
