unitTest 維護與測試及使用
目前專案的 npm test 就等於 npm run test:unit  (package.json)  把資料夾內的 tests/unit 和 tests/component 一起跑完

npm test  一次確認目前 unit/component 測試有沒有壞
npx vitest  開發中持續 watch，改完檔案會重跑，最適合「真正拿來用」。
npx vitest run tests/unit/usePracticeSession.spec.ts  只跑單一測試檔，修 bug 時最快。
npx vitest -t "route ownership"  只跑某個案例。
npm run test:ci  本機完整模擬 CI，會跑 lint、typecheck、unit、build、e2e，定義在 package.json (line 15)。 要 push 前跑一次

tests/unit 放純邏輯測試，例如工具函式、composable 狀態流轉。 改 utils 或 composables 時，同步更新
tests/component 放 Vue 元件行為測試，像 route 對應顯示什麼 panel。可參考 RouteOwnership.spec.ts (line 7)。 改畫面條件渲染、互動或 provider/inject 時，同步更新
tests/e2e 放完整使用流程，不要把 e2e 的責任塞進 unit test。

DOM 選取盡量用穩定 selector，例如現在已有的 data-testid 做法。

Vitest 測試執行工具(一種常見套件)，會抓 *.test.ts 以及 *.spec.ts 當作測試檔
Vitest 預設是在 Node.js 環境跑。但 Node.js 本身沒有真的瀏覽器畫面，也沒有完整的 DOM。jsdom 就是一個「用 JavaScript 模擬瀏覽器 DOM 的環境」。
-----------------------------------------------------------------------------------------------
virtual:pwa-register 是 vite-plugin-pwa 提供的寫法。 registerSW 是由 vite-plugin-pwa 產生並輸出的函式。
-----------------------------------------------------------------------------------------------
E2E 是 End-to-End 測試，意思是「站在使用者角度，從最外層真的把整條流程跑一次」。

安裝 (npm ci 把 @playwright/test 安裝進 node_modules。 npx playwright install chromium：安裝「Playwright 要拿來開的瀏覽器」)
npm ci
npx playwright install chromium
平常執行：
npm run test:e2e
只跑單一檔案：
npx playwright test tests/e2e/practice-exam-flow.spec.ts
想看互動式除錯介面：
npx playwright test --ui
想看報告：
npx playwright show-report
列出幾隻E2E
npm run test:e2e -- --list

Playwright 會自動啟動網站 (playwright.config.ts裡面的webServer)

後續維護與新增
1. 挑「值得用 E2E 保護」的情境，不要先想元件，要先想使用者流程。
2. 確認這個流程有沒有穩定 selector；能用 getByRole 就用，會常變的元素就補 data-testid。
getByRole 是 Playwright 用來「用無障礙語意找元素」的方法。 ex. page.getByRole('button', { name: '開始測驗' })
3. 在 tests/e2e 新增一支 *.spec.ts，命名直接反映流程，例如 unknown-result-flow.spec.ts。
4. 共用進站、切頁、常用操作，盡量抽到 tests/e2e/testUtils.ts，不要每支測試都重寫。
