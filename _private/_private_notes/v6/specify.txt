Feature:
https://psplover16.github.io/Japanese_Word_Practice_Vue/ 是一個SPA網站，所以抓取其路由要特別處理。
將目前專案既有 `單字練習` route 的主內容，重寫為與參考頁 `https://psplover16.github.io/Japanese_Word_Practice_Vue/word-practice` 主內容高度一致的版本。
該內容是一個類似字典，但具有學習、紀錄功能的網站。

本次需求不是新增 route，也不是重做整個 app shell。
本次需求是保留目前專案既有的：
1. route path
2. route title
3. route tabs / 路由切換按鈕
4. 目前專案的外層頁面殼層

只替換上述殼層以下的「主要內容區」。

==================================================
一、需求目標
==================================================

目標不是做「相似版」。
目標是讓目前專案 `單字練習` route 的主要內容，在以下面向都盡量與參考頁一致：

1. 容器順序
2. 每個容器的標題與副標題文字
3. 每個容器內 table 的結構
4. 每個 tr / td / th 的內容與排版
5. 每個儲存格是否換行、如何換行
6. 每個儲存格的文字顏色與背景色
7. 每個儲存格的對齊方式與排版方向
8. 每個儲存格的字級、粗細、字體樣式

==================================================
二、範圍界定
==================================================

In scope

1. 目前專案 `單字練習` route 主內容的完整替換
2. 與參考頁一致的容器順序與容器數量
3. 與參考頁一致的表格結構與內容
4. 與參考頁一致的 typography / alignment / wrapping / background / border 呈現
5. 與參考頁一致的 accordion 展開/收合後內容呈現
6. 建立足夠詳細的驗收標準，供後續 CRUD 與 regression 驗證

Out of scope

1. 新增 `/word-practice` route
2. 修改目前專案 route title
3. 修改目前專案 route tabs
4. 修改其他 route 的主內容
5. 重設整個網站主題色或 app shell 配色

==================================================
三、參考頁視為唯一內容基準
==================================================

本需求的主內容比對基準，明確指定為：
`https://psplover16.github.io/Japanese_Word_Practice_Vue/word-practice`

若目前專案內容與參考頁衝突，應以參考頁為準。
若本地已存在較舊或較簡化的 grammar 規則資料，視為廢棄內容。

==================================================

作為使用者，我進入目前專案的 `單字練習` route 時，
希望在不改變既有 route title 與 route tabs 的前提下，
看到與參考頁一致的主要內容區。

希望看到與參考頁一致的 table 內容、結構與視覺排版，

五、功能需求
==================================================

0. 沒特別標註的隱藏，表示完全消失，版面不留佔位
1. 此處是希望做一個字典，目前我有一個JS檔案，請轉成ts檔案在使用，該檔案是字典檔，@/_private/_private_notes/v6/jpWords.js
該字典檔可以在頁面下方的表格生成資料，原則上 利用內容來決定 td 的大小。
2. 表格的內容有以下這些，標頭 本身就有checkbox的功能，以下分別介紹他們每一列的功能及其標頭的checkbox勾選功能
 2-0. 此處td的隱藏規則預設是：標頭的checkbox 勾選時，會顯示該 日文字所對應的內容，但沒勾選，內容會隱藏，但仍有佔位；而非完全隱藏
 2-1. 單字，日語的單字。在input下方的 練習 checkbox被勾選後，平假名及片假名會互換，ex. かさ >> カサ
  標頭的 單字checkbox預設是勾選狀態，規則同2-0
 2-2. 漢字與拚音，兩者的標頭、內容 共用一個td，內容會隨著 input旁邊的 漢字 checkbox被勾選的有無，決定顯示哪個。 預設 input旁邊的 漢字checkbox是被勾選的
  2-2-1. 漢字，日語的漢字。input旁邊的 漢字 checkbox被勾選時，才會顯示。 table中，標頭的 漢字checkbox 預設沒被勾選，規則同2-0
  2-2-2. 拼音，羅馬拼音。 input旁邊的 漢字 checkbox沒被勾選時，才會顯示。 table中，標頭的 拼音checkbox 預設沒被勾選，規則同2-0
 2-3. 中文，日語的中文翻譯。table中，標頭的 中文checkbox 預設沒被勾選，規則同2-0
 2-4. 空白checkbox，此處比較特別，沒有label，標題及實際內容都有checkbox，但規則皆不同。此處的td有固定大小
  2-4-1. 實際內容的checkbox，被勾選時，在按下按鈕儲存註記，會把該列的單字儲存起來。表示不會、不熟悉的單字。
    A. 被註記的單字會影響該列的背景色，當作提示功能，且被註記的單字的checkbox是被勾選的。
    B. 使用者可藉由勾選checkbox，在按下按鈕 儲存註記，重新對被勾選的內容做更動。
    C. 使用者下一次進入網頁，需要可以看到上次儲存註記提示。
  2-4-2. 標頭的checkbox，功能與按鈕雷同，checkbox本身不會改變狀態。當被按下時，會跳出警告  確定要刪除全部註記嗎？ 按下確定後，再跳第二個警告，刪除後，無法復原，確定要刪除嗎？ 再案確定後，會把 2-4-1 所儲存的內容全部刪除。
3. 目前在 路由：字母練習，所勾選的字母，在其他路由可以抓取的到。
想要的功能是在根據在子母練習所沒有被勾選的字母，去搜尋該字典檔。沒有被勾選的，原則上，不顯示。
比如說，只勾選 題目包含：平假名 以及 清音表格的 あ / ア，那整份字典的單字只有 あ 才可以顯示。
勾選了 題目包含：平假名 及 題目包含：片假名 以及 清音表格的 あ / ア，那整份字典的單字只有 あ、ア 才可以顯示。
但勾選了 題目包含：平假名 以及 清音表格的 あ / ア 以及 清音表格的 さ / サ，那整份字典的單字只有 あ、さ 才可以顯示。
但勾選了 題目包含：平假名 及 題目包含：片假名 以及 清音表格的 あ / ア 以及 清音表格的 さ / サ，那整份字典的單字只有 あ、ア、さ、サ 才可以顯示。
4. input 是即時搜尋，符合條件的才搜尋，搜尋範圍包含中文(翻譯)、羅馬音(拼音)、日文中的漢字
5. 旁邊的checkbox是條件，input及inoput旁邊及下方的checkbox的條件 是 疊加關係，也就是都要同時滿足，才會顯示
  5-1. 全部字音是勾選後 無視第2條的規則，全部顯示，預設是勾選狀態；
  5-2. 漢字 checkbox的功能，在 2-2 有提到
  5-3. 只顯示註記 checkbox的功能，被勾選後 只有根據 2-4-1 勾選的內容會顯示，其他則隱藏。
  5-4. 練習checkbox，功能在 2-1 有提到
6. 與儲存註記同行，有一個 文字提示，個單字， 他是表示符合目前搜尋狀態，單字的數量，該單字的量，應該要與與table中扣除標頭後，剩下的tr的數量相同。ex. 1077個單字
7. 在table實際內容處，若長按(包含手機、PC)約0.5秒，則把該列 顯示的內容全部顯示，持續長按，會持續顯示。放開長按，該列會回到原本的顯示狀態。

==================================================
六、詳細驗收標準
==================================================

以下 6 大類驗收，全部都必須對每一個容器逐項檢查。

AC-A 結構驗收：tr / td / th / colspan / rowspan

每一個容器都必須驗收：
1. table 的存在數與順序是否一致
2. table 是否使用正確的 thead / tbody / tfoot 結構
3. 每個 tr 的順序是否一致
4. 每個 td / th 的數量是否一致
5. 每個 colspan 值是否一致
6. 每個 rowspan 值是否一致
7. td的 width 是否一致

AC-B 文字驗收：每個文字內容

每一個容器都必須驗收：
1. 標題是否逐字一致
2. 副標題是否逐字一致
3. 每個儲存格主文字是否逐字一致
4. 範例文字是否逐字一致
5. 標點、括號、全形符號、日文假名是否一致
6. 編號樣式是否一致
7. 任何說明列、表尾註記是否一致

AC-C 換行驗收：td 內容是否允許斷行

每一個容器都必須驗收：
1. 哪些表頭不換行
2. 哪些欄位允許換行
3. 哪些欄位需要保留多行
4. 副標題是否分多行
5. 範例區是否在主文字下方換行呈現
6. 手機寬度下換行後是否仍維持與參考頁相同閱讀順序

AC-D 色彩驗收：文字色、td / tr 背景色

每一個容器都必須驗收：
1. 表頭背景色是否一致
2. 一般儲存格背景是否一致
3. 特殊高亮儲存格背景是否一致
4. 表尾背景是否一致
5. 主文字色與次文字色是否一致
6. 需要強調的特殊儲存格是否保留強調色

AC-E 排版驗收：水平/垂直、置左/置中/置右

每一個容器都必須驗收：
1. 表頭對齊是否一致
2. 一般儲存格對齊是否一致
3. 多行內容是否左對齊堆疊
4. 需要置中的欄位是否維持置中
5. 需要水平排列的內容是否未被改為垂直排列
6. 巢狀清單的縮排與排列方向是否一致

AC-F 字體驗收：大小、粗細、font style

每一個容器都必須驗收：
1. 標題字級與粗細是否一致
2. 副標題字級與粗細是否一致
3. 表頭字級與粗細是否一致
4. 一般儲存格字級與粗細是否一致
5. 次要範例字級與顏色是否一致
6. 巢狀清單中的強調字是否維持粗體或強調樣式

AC-G 功能驗收：input及各個checkbox是否會正確影響到 實際 table顯示的內容
每一個input及checkbox都必須驗收：
1. input搜尋功能，功能是否符合預期，是否有成功顯示出正確的 表格內容
2. input旁邊及下方的 checkbox，功能是否符合預期，是否有成功顯示出正確的 表格內容
3. input及 checkbox的疊加狀態，功能是否符合預期，是否有成功顯示出正確的 表格內容
4. 儲存註記的功能是否有正確儲存
5. 單字數量是否有正確計算，表格內容是否正確

==================================================
七、容器級驗收要求
==================================================

每一個容器都必須至少完成以下驗收紀錄：

1. 容器標題對照
2. 容器副標題對照
3. table 結構對照
4. 每列文字內容對照
5. 換行規則對照
6. 色彩對照
7. 對齊對照
8. 字級/粗細對照

也就是說，本功能的驗收不是只驗「整頁看起來像」。
而是必須能逐容器、逐 table、逐列、逐儲存格進行檢查。
