Feature:
將目前專案既有 `變化規則` route 的主內容，重寫為與參考頁
`https://psplover16.github.io/Japanese_Word_Practice_Vue/change-rules`
主內容高度一致的版本。

本次需求不是新增 route，也不是重做整個 app shell。
本次需求是保留目前專案既有的：
1. route path
2. route title
3. route tabs / 路由切換按鈕
4. 目前專案的外層頁面殼層

只替換上述殼層以下的「主要內容區」。

==================================================
一、需求目標
==================================================

目標不是做「相似版」。
目標是讓目前專案 `變化規則` route 的主要內容，在以下面向都盡量與參考頁一致：

1. 容器順序
2. 每個容器的標題與副標題文字
3. 每個容器內 table 的結構
4. 每個 tr / td / th 的內容與排版
5. 每個儲存格是否換行、如何換行
6. 每個儲存格的文字顏色與背景色
7. 每個儲存格的對齊方式與排版方向
8. 每個儲存格的字級、粗細、字體樣式

==================================================
二、範圍界定
==================================================

In scope

1. 目前專案 `變化規則` route 主內容的完整替換
2. 與參考頁一致的容器順序與容器數量
3. 與參考頁一致的表格結構與內容
4. 與參考頁一致的 typography / alignment / wrapping / background / border 呈現
5. 與參考頁一致的 accordion 展開/收合後內容呈現
6. 建立足夠詳細的驗收標準，供後續 CRUD 與 regression 驗證

Out of scope

1. 新增 `/change-rules` route
2. 修改目前專案 route title
3. 修改目前專案 route tabs
4. 修改其他 route 的主內容
5. 重設整個網站主題色或 app shell 配色

==================================================
三、參考頁視為唯一內容基準
==================================================

本需求的主內容比對基準，明確指定為：
`https://psplover16.github.io/Japanese_Word_Practice_Vue/change-rules`

若目前專案內容與參考頁衝突，應以參考頁為準。
若本地已存在較舊或較簡化的 grammar 規則資料，視為廢棄內容。

==================================================
四、主要使用者故事
==================================================

User Story 1
作為使用者，我進入目前專案的 `變化規則` route 時，
希望在不改變既有 route title 與 route tabs 的前提下，
看到與參考頁一致的主要內容區。

User Story 2
作為使用者，我展開任一容器時，
希望看到與參考頁一致的 table 內容、結構與視覺排版，
而不是經過簡化或摘要化的版本。

User Story 3
作為使用者，我在手機與桌機閱讀時，
希望表格的換行規則、對齊方式、字級與背景層次都和參考頁一致，
不會因為本地實作不同而讓閱讀感受改變。

User Story 4
作為後續維護者，我希望規格文件中明確記錄每個驗收面向，
讓後續 CRUD、修文案、補表格或做回歸驗證時，有清楚的對照標準。

==================================================
五、主內容容器清單
==================================================

目前規格預期容器順序需與參考頁一致，至少包含以下 12 個容器：

1. 語法系統差異
2. 各活用型意義
3. 動詞型態分辨: 一段/五段/不規則
4. 五段動詞表(詞尾母音變化)
5. 音便 (詞尾接尾一起改變)
6. 一段動詞 (辭書型 結尾必定是 る)
7. サ變動詞 (する動詞為結尾的動詞)
8. カ變動詞 (只有来る)
9. い形容詞
10. ない形容詞
11. だ助動詞
12. 詞性變化規則

若參考頁中容器標題包含副標題或額外說明文字，
本地也必須保留，且換行方式需一致。

==================================================
六、功能需求
==================================================

FR-01
系統必須保留目前專案既有的 `變化規則` route path、route title、route tabs 與外層殼層。

FR-02
系統必須移除目前專案既有 `變化規則` route 的舊主內容，改為參考頁主內容的重寫版。

FR-03
系統必須使主內容容器的數量、順序、標題、副標題與參考頁一致。

FR-04
系統必須使每一個容器內的 table 結構與參考頁一致，包含但不限於：
1. table 數量
2. thead / tbody / tfoot 是否存在
3. tr 數量
4. td / th 數量
5. colspan
6. rowspan
7. 儲存格巢狀清單
8. 儲存格內段落與換行

FR-05
系統必須使每個表格儲存格的文字內容與參考頁一致，包含：
1. 中文
2. 日文
3. 括號
4. 標點
5. 空白
6. 範例文字
7. 編號格式

FR-06
系統必須使每個儲存格的換行行為與參考頁一致，包含：
1. 允許換行或不允許換行
2. 單行呈現或多行呈現
3. 文字是否因 `whitespace-pre-wrap`、`nowrap`、一般流式文字而表現不同
4. 副標題是否保留手動換行

FR-07
系統必須使每個儲存格與列的視覺樣式與參考頁一致，包含：
1. 文字顏色
2. 儲存格背景色
3. 特殊列背景色
4. 特殊儲存格高亮色
5. 表頭色塊
6. 邊框存在與層次

FR-08
系統必須使每個儲存格的對齊與排版方向與參考頁一致，包含：
1. 水平排版或垂直堆疊
2. 文字置左、置中、置右
3. 上對齊、中央對齊
4. 清單縮排層級
5. 範例文字與主文字的相對位置

FR-09
系統必須使文字樣式與參考頁一致，包含：
1. 字級
2. font weight
3. 是否為粗體
4. 是否為次要字級
5. 是否有特定強調文字

FR-10
系統必須保留 accordion 互動，且展開後內容不能因樣式套用而破壞參考頁 table 結構。

FR-11
系統必須提供可持續維護的規格與驗收基準，讓後續 CRUD 能知道：
1. 哪個容器改了
2. 改了哪種 table 結構
3. 哪個儲存格文字有變更
4. 哪個樣式面向需要重新驗收

==================================================
七、詳細驗收標準
==================================================

以下 6 大類驗收，全部都必須對每一個容器逐項檢查。

AC-A 結構驗收：tr / td / th / colspan / rowspan

每一個容器都必須驗收：
1. table 的存在數與順序是否一致
2. table 是否使用正確的 thead / tbody / tfoot 結構
3. 每個 tr 的順序是否一致
4. 每個 td / th 的數量是否一致
5. 每個 colspan 值是否一致
6. 每個 rowspan 值是否一致
7. 是否有巢狀清單、範例列、附註列
8. 特殊結構是否保留，例如：
   - 五段動詞表中的 row span 合併
   - 音便容器的表尾說明區
   - 詞性變化規則中的巢狀清單

AC-B 文字驗收：每個文字內容

每一個容器都必須驗收：
1. 標題是否逐字一致
2. 副標題是否逐字一致
3. 每個儲存格主文字是否逐字一致
4. 範例文字是否逐字一致
5. 標點、括號、全形符號、日文假名是否一致
6. 編號樣式是否一致
7. 任何說明列、表尾註記是否一致

AC-C 換行驗收：td 內容是否允許斷行

每一個容器都必須驗收：
1. 哪些表頭不換行
2. 哪些欄位允許換行
3. 哪些欄位需要保留多行
4. 副標題是否分多行
5. 範例區是否在主文字下方換行呈現
6. 手機寬度下換行後是否仍維持與參考頁相同閱讀順序

AC-D 色彩驗收：文字色、td / tr 背景色

每一個容器都必須驗收：
1. 表頭背景色是否一致
2. 一般儲存格背景是否一致
3. 特殊高亮儲存格背景是否一致
4. 表尾背景是否一致
5. 主文字色與次文字色是否一致
6. 需要強調的特殊儲存格是否保留強調色

AC-E 排版驗收：水平/垂直、置左/置中/置右

每一個容器都必須驗收：
1. 表頭對齊是否一致
2. 一般儲存格對齊是否一致
3. 多行內容是否左對齊堆疊
4. 需要置中的欄位是否維持置中
5. 需要水平排列的內容是否未被改為垂直排列
6. 巢狀清單的縮排與排列方向是否一致

AC-F 字體驗收：大小、粗細、font style

每一個容器都必須驗收：
1. 標題字級與粗細是否一致
2. 副標題字級與粗細是否一致
3. 表頭字級與粗細是否一致
4. 一般儲存格字級與粗細是否一致
5. 次要範例字級與顏色是否一致
6. 巢狀清單中的強調字是否維持粗體或強調樣式

==================================================
八、容器級驗收要求
==================================================

每一個容器都必須至少完成以下驗收紀錄：

1. 容器標題對照
2. 容器副標題對照
3. table 結構對照
4. 每列文字內容對照
5. 換行規則對照
6. 色彩對照
7. 對齊對照
8. 字級/粗細對照

也就是說，本功能的驗收不是只驗「整頁看起來像」。
而是必須能逐容器、逐 table、逐列、逐儲存格進行檢查。

==================================================
九、成功標準
==================================================

1. 使用者進入目前專案 `變化規則` route 時，主內容區與參考頁主內容在結構與視覺上高度一致。
2. 12 個容器皆可逐一展開，且內容無缺漏、無錯字、無錯位、無錯色。
3. 任一容器中的表格都可通過上述 6 大類驗收。
4. 文件中已提供足夠詳細的 acceptance，後續維護者可依此進行 CRUD 與 regression 驗證。

==================================================
十、明確假設
==================================================

1. 參考頁為目前需求的唯一正確版本。
2. 既有 route shell 保留，主內容完全替換。
3. 若為了達成與參考頁一致，需要使用較低抽象程度的 table 資料結構，視為可接受。
4. 若目前專案中已存在較簡化的 grammar 資料模型，可為此需求調整。
