這份檔案是給 githubSpecKit clarify 階段使用的。
重點是避免後續 spec / plan / tasks 誤以為要新做一個 route，或誤以為頁首也要一起重現。

如果 clarify 階段需要問問題，請優先針對下列重點澄清。
如果沒有真的進入提問流程，也請把以下內容視為預設答案。

一、這次 feature 的真正 scope 是什麼？
建議答案：
- 這次 feature 的 scope 是「目前專案既有 `變化規則` 路由內的主要內容區」
- 不是新增一條新的 `change-rules` route
- 不是重做整個頁首與路由切換按鈕

原因：
- 這是使用者最新補充的核心需求，不能再誤解

二、目前專案的路由標題與切換按鈕要不要改？
建議答案：
- 不改
- 頁首標題與 route tabs 保持目前專案既有寫法與行為
- 這次只替換它們下方的主要內容

原因：
- 使用者已明確指定這兩者要保留

三、是否需要新增 `/change-rules` 路由？
建議答案：
- 不需要
- 應直接在目前專案的 `變化規則` 路由內改寫內容
- 若目前專案此 route path 是 `/grammar`，那就維持 `/grammar`

原因：
- 需求是替換既有 route 主內容，不是加新 route

四、目前 `變化規則` 路由原有內容如何處理？
建議答案：
- 視為廢棄
- 應由新內容完全取代
- 不應保留舊內容與新內容並存

原因：
- 使用者已明確表示目前專案的變化規則路由內容廢棄

五、參考頁面中哪些部分要被搬進來？
建議答案：
- 只搬「最上方路由標題與路由切換按鈕以下的主要內容」
- 不搬參考頁自己的頁首標題與三顆按鈕

原因：
- 本次重寫的是主內容，不是整個 frame

六、配色是否要複製參考網站？
建議答案：
- 不用
- 配色應依照目前專案既有配色系統
- 但資訊架構、章節順序、互動與閱讀節奏可高度參考外部頁面

原因：
- 使用者已明示「配色可以依照目前專案的配色」

七、主內容重現等級
建議答案：
- 高相似度重寫主內容
- 優先重現章節順序、主要可見文字、表格資訊結構與展開/收合互動
- 不要求逐像素複製外部站配色與頁首

原因：
- 這樣才能同時滿足「內容參考外部頁」與「殼層沿用目前專案」

八、accordion / 章節互動
建議答案：
- 所有章節預設收合
- 點擊章節標題列可展開/收合
- 允許多個章節同時展開

原因：
- 這與目前參考頁實際觀察一致

九、資料來源策略
建議答案：
- 必須改寫成本專案內部的靜態結構化資料
- 不允許 runtime 抓外部頁面 DOM 或 HTML

原因：
- 後續要方便 CRUD，且要可維護、可測試、可離線

十、這次是否要為 CRUD 預留設計？
建議答案：
- 要
- 章節、子標題、補充說明、表頭、表列、例句都應可獨立調整
- 不要把大段內容直接鎖死在單一 template

原因：
- 這是使用者這次特別強調的需求

十一、頁面底部狀態文字是否納入？
建議答案：
- 預設納入這次主內容重寫範圍，因為它們位於頁首以下
- 但需在 plan 階段明確判斷是：
  1. route 專屬主內容的一部分
  2. 還是應與目前專案既有 PWA 狀態顯示整合

原因：
- 這一段位於主內容範圍內，但與全域 PWA 顯示責任可能重疊

十二、這次 out of scope
建議答案：
- 不做新的 route shell
- 不重做目前專案上方路由切換按鈕
- 不重做其他 route 內容
- 不做後台管理介面
- 不做外部同步或資料庫

如果 clarify 要濃縮成最重要的決策，至少請固定這六點：
1. 本次是重寫既有 `變化規則` route 主內容，不是新增 route
2. 頁首標題與 route tabs 保持不變
3. 既有主內容完全廢棄並被取代
4. 新主內容高度參考外部頁面在頁首以下的部分
5. 配色跟隨目前專案，不跟隨參考站
6. 內容來源必須是本地結構化資料，以支援後續 CRUD
