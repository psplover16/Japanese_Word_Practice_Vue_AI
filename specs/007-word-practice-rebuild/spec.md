## Clarifications

### Session 2026-04-02

- Q: 儲存功能? → A: 具有記憶功能，讓使用者知道上次學習的狀況。
- Q: 上次儲存的資料有誤? → A: 進入該 route 時需先驗證上次儲存格式；若格式不正確就刪除舊資料避免 bug。儲存註記時若格式不正確，不能儲存，且需顯示警告。
- Q: 參考頁底部版號是否一併重建? → A: 本 feature 雖以參考頁為主要版面基準，但最下方版號不跟抄。

## User Scenarios & Testing

### User Story 1 - 使用者看到完整單字練習頁 (Priority: P1)

作為進入 `單字練習` 頁的使用者，我希望在保留既有 `/vocabulary` 路由、頁面標題與分頁切換的前提下，看到與參考頁一致的主要內容區，而不是目前的簡化 placeholder 或舊版內容。

**Why this priority**: 這是本功能的核心價值；若主內容沒有被完整替換，後續所有搜尋、篩選、註記與驗收都失去基礎。

**Independent Test**: 只實作這個故事時，使用者可直接開啟 `/vocabulary`，確認 route title、route tabs 與 app shell 保持不變，且主內容區已替換為參考頁對應的控制區、單字數量摘要與單一可捲動表格。

**Acceptance Scenarios**:

1. **Given** 使用者進入 `/vocabulary`，**When** 頁面完成初始渲染，**Then** 畫面仍保留既有 route title、route tabs 與 app shell，且主內容區顯示與參考頁一致的控制區、表格與資訊區塊。
2. **Given** 使用者在 `/vocabulary` 與其他 routes 之間切換，**When** 再返回 `/vocabulary`，**Then** 新版主內容仍穩定顯示，不會退回舊版簡化內容或共享其他 route 的 UI。

---

### User Story 2 - 使用者依條件篩選與搜尋單字 (Priority: P2)

作為查找日文單字的使用者，我希望能依字母練習頁目前勾選的字音、搜尋 input 與多個 checkbox 條件共同篩選資料，讓表格只顯示符合條件的單字列與欄位內容。

**Why this priority**: 這是主內容區最主要的互動價值；若搜尋與條件疊加不正確，頁面即使外觀相似，也無法作為可用的學習字典。

**Independent Test**: 打開 `/vocabulary`，搭配 `/practice` 已勾選的字母與頁面上的 input / checkbox 條件，確認表格僅顯示符合條件的資料列，且單字數量提示與可見列數一致。

**Acceptance Scenarios**:

1. **Given** 使用者已在 `/practice` 勾選特定平假名或片假名，**When** 開啟 `/vocabulary`，**Then** 表格只顯示符合目前題目範圍與已勾選字母的單字資料。
2. **Given** 使用者在 `/vocabulary` 輸入搜尋字詞，**When** 搜尋字詞符合中文、羅馬音或日文漢字內容，**Then** 表格只保留符合搜尋字詞且同時滿足其他條件的資料列。
3. **Given** 使用者調整 input 旁邊或下方的 checkbox，**When** 任一條件變動，**Then** 顯示結果必須即時更新，且各條件採疊加關係而非互相覆蓋。
4. **Given** 使用者檢視符合目前條件的資料，**When** 表格完成渲染，**Then** 表頭下方的資料列數量與畫面上的單字數量提示必須一致。

---

### User Story 3 - 使用者控制欄位顯示、練習與註記 (Priority: P3)

作為學習單字的使用者，我希望可以控制單字、漢字／拼音、中文與註記欄位的顯示方式，並能保存不熟悉單字的註記，讓頁面同時支援閱讀、練習與持久化提示。

**Why this priority**: 這一層互動直接影響頁面的學習用途；沒有欄位控制、註記與練習模式，頁面只會是一張靜態表格，而不是參考頁等級的學習工具。

**Independent Test**: 在 `/vocabulary` 中切換各欄位 checkbox、啟用練習模式、勾選列內註記 checkbox 並重新整理頁面，確認顯示狀態、背景提示與持久化結果都符合預期。

**Acceptance Scenarios**:

1. **Given** 使用者切換欄位標頭 checkbox，**When** 取消勾選某一欄位，**Then** 該欄位內容必須隱藏但保留原本表格佔位與欄寬，不可整欄移除。
2. **Given** 使用者切換「漢字」全域 checkbox，**When** 其狀態改變，**Then** 漢字／拼音共用欄位必須在相同欄位位置切換顯示內容，而不是額外增減欄位。
3. **Given** 使用者勾選「練習」checkbox，**When** 表格顯示單字欄位，**Then** 單字中的平假名與片假名必須依參考頁規則互換呈現。
4. **Given** 使用者勾選某列註記 checkbox 並按下儲存註記，**When** 表格重新渲染或頁面重新載入，**Then** 該列必須保留註記狀態、顯示提示背景色，並可在下次進站時看到同一提示。
5. **Given** 使用者使用註記欄標頭的清除 checkbox，**When** 連續確認兩次刪除警告，**Then** 所有已儲存註記都必須被清空，且此標頭 checkbox 本身不因操作而維持勾選狀態。
6. **Given** 使用者進入 `/vocabulary` 或嘗試儲存註記，**When** 系統發現既有持久化資料格式錯誤，**Then** 進站時必須自動刪除錯誤舊資料，儲存時必須阻止寫入並顯示警告。

### User Story 4 - 使用者在不同裝置維持一致閱讀與互動 (Priority: P4)

作為在手機、平板與桌機上閱讀的使用者，我希望表格結構、儲存格換行、對齊方式、顏色層次、字級與長按顯示行為都與參考頁一致，避免不同裝置出現閱讀順序改變、欄位錯位或功能失真。

**Why this priority**: 這個頁面同時重視 fidelity 與互動細節；若窄版排版或長按行為失真，使用者就無法取得與參考頁一致的學習體驗。

**Independent Test**: 在桌機與窄版 viewport 開啟 `/vocabulary`，比對表格結構、欄位換行、色彩階層與長按顯示行為是否與參考頁一致，且不出現遮蓋、重疊或不可讀情況。

**Acceptance Scenarios**:

1. **Given** 使用者在手機或桌機寬度瀏覽 `/vocabulary`，**When** 表格與控制區顯示，**Then** 各容器、table、checkbox 與 input 的位置、寬度與閱讀順序都必須符合參考頁。
2. **Given** 使用者長按任一資料列約 0.5 秒，**When** 長按持續中，**Then** 該列原本因欄位設定而被隱藏的可顯示內容必須暫時完整顯示；放開後需立即回到原本顯示狀態。
3. **Given** 使用者在窄版畫面檢視表格，**When** 欄位發生換行，**Then** 不得出現順序顛倒、文字重疊、欄寬錯亂或互動目標不可點擊的狀況。

---

### User Story 5 - 維護者有足夠明確的驗收與對照基準 (Priority: P5)

作為後續維護者，我希望規格、計畫、任務與分析文件都清楚記錄容器順序、表格結構、條件邏輯、驗收類型與回歸範圍，讓後續 CRUD、修文案、補資料或做 regression 驗證時有可追溯基準。

**Why this priority**: 本功能是高度固定版面加上多條件互動；若缺少逐容器、逐欄位的驗收基準，後續很容易在修改時破壞 fidelity 或邏輯。

**Independent Test**: 僅查看 spec、plan、tasks、analyze 與測試文件，即可辨識本功能的資料來源、作用路由、驗收面向與不得外溢的範圍。

**Acceptance Scenarios**:

1. **Given** 維護者需要修改某一個容器或欄位，**When** 查閱規格與任務，**Then** 可以定位對應的資料來源、顯示規則與應回歸的驗收面向。
2. **Given** 維護者需要驗證頁面是否回歸，**When** 依文件與測試執行驗收，**Then** 能逐容器、逐 table、逐列、逐欄位檢查結構、文字、換行、色彩、對齊與字體。

---

### Edge Cases

- 若 `/practice` 尚未勾選任何可對應字音，`/vocabulary` 仍需安全渲染，不得出現 runtime error、render failure 或 browser console error，且空結果需維持合法版面。
- 若搜尋字詞為空字串、全形空白、無匹配結果或只命中部分條件，頁面需即時呈現正確的空結果狀態與單字數量，不得殘留舊資料列。
- 若欄位內容被 header checkbox 隱藏，該欄位仍必須保留固定佔位與欄寬，不得因隱藏造成整列結構塌陷。
- 若漢字與拼音共用欄位切換顯示內容，欄位寬度、對齊與表頭結構不得改變。
- 若註記資料不存在、資料損毀或被全部清除，頁面必須回到未註記狀態，不得保留錯誤背景色或殘留勾選。
- 若進站時讀到的既有持久化資料格式錯誤，系統必須先清除該資料再繼續渲染，避免因錯誤格式導致 bug。
- 若使用者執行儲存註記時資料格式驗證失敗，系統必須拒絕儲存並顯示警告，不得寫入不合法資料。
- 若使用者長按列內容期間切換裝置輸入事件或放開手指／滑鼠，列內容必須正確恢復原始顯示，不得卡在暫時展開狀態。
- 本功能只作用於 `/vocabulary` 主內容；`/practice`、`/grammar`、route tabs、route title、app shell 與其他 routes 都必須維持既有行為。
- 若現有共用樣式或元件無法忠實表達參考頁版型，可在 `/vocabulary` 模組中採用 route-specific 結構與樣式，但不得把不適合的共享樣式強行套用到此頁。

## Requirements

### Functional Requirements

- **FR-001**: 系統 MUST 保留既有 `/vocabulary` route path、route title、route tabs 與 app shell，不得因本功能改變這些外層導覽與殼層結構。
- **FR-002**: 系統 MUST 將 `/vocabulary` 目前的舊主內容完整替換為參考頁 `https://psplover16.github.io/Japanese_Word_Practice_Vue/word-practice` 的重建版本。
- **FR-003**: 系統 MUST 讓 `/vocabulary` 主內容中的容器數量、順序、控制區、單字數量摘要列與單一可縱向捲動的表格區塊與參考頁一致。
- **FR-004**: 系統 MUST 以既有提供的字典資料作為單字表格的資料來源，保留其單字、漢字、拼音、中文翻譯與可供篩選的字音資訊。
- **FR-005**: 系統 MUST 讓表格的 `thead`、`tbody`、`tfoot`、`tr`、`td`、`th`、`rowspan`、`colspan`、固定欄寬與控制元件位置與參考頁一致。
- **FR-006**: 系統 MUST 讓資料列預設只顯示符合目前 `/practice` 勾選字母與題目範圍的字典資料；未符合者不得顯示在表格中。
- **FR-007**: 系統 MUST 根據 `/practice` 的平假名／片假名範圍與已勾選字母，正確過濾單字資料；當兩種字種都勾選時，需同時納入兩者可對應的字典項目。
- **FR-008**: 系統 MUST 提供即時搜尋 input，搜尋範圍至少包含中文翻譯、羅馬拼音與日文漢字，且只會在符合目前其他條件的資料集合上過濾。
- **FR-009**: 系統 MUST 讓 input 與其旁邊、下方的 checkbox 條件採疊加關係；所有條件都需同時滿足，資料列才可顯示。
- **FR-010**: 系統 MUST 提供「全部字音」checkbox；其預設為勾選，且其作用必須與參考頁一致，不得因本地重建改變資料列顯示範圍。
- **FR-011**: 系統 MUST 提供「漢字」checkbox 作為全域顯示切換；勾選時共用欄位顯示漢字，未勾選時在相同欄位位置顯示拼音。
- **FR-012**: 系統 MUST 提供「只顯示註記」checkbox；勾選後只顯示已被註記的資料列，其餘資料列必須隱藏。
- **FR-013**: 系統 MUST 提供「練習」checkbox；勾選後，單字欄中的平假名與片假名需依參考頁規則互換呈現。
- **FR-014**: 系統 MUST 在表格中提供可勾選的欄位標頭 checkbox，並依參考頁規則控制單字、漢字／拼音共用欄與中文欄的顯示與隱藏。
- **FR-015**: 系統 MUST 讓欄位標頭 checkbox 在隱藏欄位內容時保留原本表格佔位與欄寬，不得整欄移除。
- **FR-016**: 系統 MUST 讓單字欄 header checkbox 預設為勾選，漢字／拼音共用欄與中文欄 header checkbox 預設為未勾選，並遵守參考頁的顯示規則。
- **FR-017**: 系統 MUST 讓漢字與拼音共用同一欄位結構；此欄位的表頭與內容需隨全域「漢字」checkbox 狀態切換呈現內容，而非拆成兩個獨立欄位。
- **FR-018**: 系統 MUST 在資料列與註記欄提供註記互動入口；使用者勾選或點擊資料列後透過儲存註記動作保存不熟悉單字，並以該列背景色作為提示。
- **FR-019**: 系統 MUST 將已儲存的註記持久化，讓使用者下次進入頁面仍能看到相同註記狀態與提示背景。
- **FR-020**: 系統 MUST 允許使用者重新勾選註記 checkbox 並再次執行儲存註記，以更新既有註記內容。
- **FR-021**: 系統 MUST 讓註記欄標頭 checkbox 作為「清除全部註記」入口；它不是一般欄位顯示開關，點擊後需依序顯示兩次不可逆刪除確認警告，且該 checkbox 本身不因操作而維持勾選狀態。
- **FR-022**: 系統 MUST 在清除全部註記後移除所有持久化註記資料，並同步清除表格中的註記勾選與提示背景。
- **FR-023**: 系統 MUST 在控制區顯示符合目前搜尋狀態的單字數量文字，例如 `1077個單字`，且其值必須等於扣除表頭後實際可見的資料列數。
- **FR-024**: 系統 MUST 讓表格實際內容區支援手機與 PC 的長按互動；長按約 0.4 秒時，需暫時完整顯示該列目前可被揭露的內容，放開後回復原狀。
- **FR-025**: 系統 MUST 讓控制區、table、checkbox、input 在手機、平板與桌機寬度下的排版位置、結構與閱讀順序與參考頁一致。
- **FR-026**: 系統 MUST 使每個容器、表頭、儲存格、範例文字與提示文字的文字內容、標點、全形符號、日文假名與編號格式與參考頁一致。
- **FR-027**: 系統 MUST 使每個容器與表格的換行規則與參考頁一致，包含不換行欄位、多行欄位、副標題、範例區與窄版閱讀順序。
- **FR-028**: 系統 MUST 使每個容器與表格的文字顏色、背景色、強調色、表頭色塊與邊框層次與參考頁一致。
- **FR-029**: 系統 MUST 使每個容器與表格的對齊方式、水平或垂直排列、置中或置左規則與參考頁一致。
- **FR-030**: 系統 MUST 使每個容器與表格的字級、粗細與字體樣式與參考頁一致。
- **FR-031**: 系統 MUST 將本功能的出現範圍限制在 `/vocabulary` 主內容；不得在 `/practice`、`/grammar` 或其他 routes 顯示本功能專屬內容。
- **FR-032**: 系統 MUST 提供對應測試與驗收檢查，涵蓋 route ownership、初始渲染、控制區互動、註記持久化、長按顯示、表格 fidelity 與窄版穩定性。
- **FR-033**: 若本功能調整了 `/vocabulary` 模組結構、靜態資料來源、測試結構、共享工具或 route 模組邊界，系統 MUST 同步更新 `PROJECT_ARCHITECTURE.md`。
- **FR-034**: 系統 MUST 讓本功能的驗收可逐容器、逐 table、逐列、逐儲存格檢查結構、文字、換行、色彩、對齊與字體，不得只以「整頁看起來相似」作為完成標準。
- **FR-035**: 系統 MUST 在進入 `/vocabulary` 時先驗證既有持久化學習資料與註記資料的格式；若格式不正確，必須清除錯誤資料後再繼續渲染。
- **FR-036**: 系統 MUST 在使用者執行儲存註記時驗證待寫入資料格式；若格式不正確，必須阻止儲存並顯示警告。
- **FR-037**: 系統 MUST 讓頁面保留參考頁的主要內容與互動結構，但不得照抄參考頁最下方的版號內容。

### Key Entities

- **VocabularyEntry**: 代表字典中的單一單字資料，包含單字、對應漢字、羅馬拼音、中文翻譯、字音資訊與可供篩選的顯示屬性。
- **VocabularyFilterState**: 代表 `/vocabulary` 頁目前的搜尋字詞、全域 checkbox 狀態、欄位顯示狀態、只顯示註記模式、練習模式與來自 `/practice` 的字母範圍條件。
- **VocabularyColumnVisibility**: 代表單字、漢字／拼音共用欄與中文欄是否顯示內容、是否保留佔位，以及各欄是否受全域切換影響的欄位呈現規則。
- **VocabularyMarkRecord**: 代表使用者儲存的不熟悉單字註記，包含單字識別、註記狀態、更新時間與對應的提示顯示需求。
- **VocabularyRevealState**: 代表長按期間某一資料列的暫時揭露狀態，用於控制按壓期間顯示全部內容、放開後恢復原狀。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 使用者進入 `/vocabulary` 後，100% 能在一次頁面載入內看到保留既有 app shell 的新版主內容，而不再看到舊版 placeholder。
- **SC-002**: 使用者切換 `/practice` 勾選字母、搜尋 input 與頁面 checkbox 條件後，100% 都能看到與條件相符的資料列，且單字數量文字與實際可見列數一致。
- **SC-003**: 使用者儲存註記並重新整理頁面後，100% 已儲存註記都能被重新載入並套用到對應資料列的勾選狀態與提示背景。
- **SC-004**: 在桌機與約 375px 寬度下檢視 `/vocabulary` 時，至少 90% 的主要容器與表格區塊不需額外解釋即可依參考頁閱讀順序理解內容，且不得出現遮蓋、重疊或不可操作的情況。
- **SC-005**: 維護者可依 spec、plan、tasks、analyze 與測試，在 10 分鐘內定位任一控制項、欄位或容器的資料來源、顯示規則與應回歸的驗收面向。

## Repository Hygiene

- 實作前確認 repository 已包含 `.gitignore`。
- 不提交 `node_modules/`。
- 不提交可重新產生的產物，例如 `build/`、`dist/`、`coverage/`，除非本規格另有明確例外。
- 若本功能變更了 `/vocabulary` 模組結構、字典資料載入方式、共享工具、route 責任邊界或測試結構，必須同步更新 `PROJECT_ARCHITECTURE.md`。

## Assumptions

- 參考頁 `https://psplover16.github.io/Japanese_Word_Practice_Vue/word-practice` 視為本功能唯一正確基準。
- 既有 `/vocabulary` 外層 route shell 會保留，但主內容可完全替換。
- 本功能保留參考頁主要內容 fidelity，但不複製參考頁底部版號。
- 與欄位顯示、顏色、換行、對齊與字體相關的細節，若本地實作與參考頁衝突，應以參考頁為準。
- 本功能可直接使用既有提供的字典資料作為單字來源；資料格式如何轉換屬規劃與實作階段處理，但不得改變資料語意。
- 若為了忠實表達參考頁，需要採用較低抽象程度的資料結構、route-specific renderer 或 route-specific 樣式，視為可接受。
