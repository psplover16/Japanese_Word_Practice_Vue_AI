# Quickstart: `/practice` 羅馬音排版補強與首屏穩定化

## 1. 安裝與啟動

```bash
npm ci
npm run dev
```

## 2. 主要驗證流程

### 流程 A：長音規則大表格

1. 進入 `/practice`。
2. 找到長音規則區塊，確認它是一張單一大表格而不是多卡片。
3. 確認規則說明列獨占整列。
4. 抽查多筆例字，確認都依序顯示假名、羅馬音、中文意思。
5. 特別檢查「あ段 + う 不一定屬於規則長音」，確認已改成多筆例字/短語，而不是單一說明文字。
6. 確認表格沒有額外出現「假名 / 羅馬音 / 中文」欄位標題字樣。

### 流程 B：清音拗音與合拗音全表羅馬音

1. 在 `/practice` 找到清音拗音區塊。
2. 抽查標頭列、列標頭與內容格，確認所有假名都附有羅馬音。
3. 找到合拗音區塊並重複上述檢查。
4. 抽查本期調整範圍中的例字，確認同時提供中文意思。

### 流程 C：外來語擴張矩陣

1. 在 `/practice` 找到外來語擴張區塊。
2. 確認第一列為母音標頭，第一欄為常見外來語基底音。
3. 抽查多個內容格，確認它們都能對應到某一列與某一欄的組合。
4. 確認每個內容格為「假名在上、羅馬音在下」，且假名不換行。

### 流程 D：首次開啟穩定顯示

1. 重新整理 `/practice`，不要做任何互動。
2. 觀察濁音／半濁音以下的區塊是否首屏就穩定出現。
3. 確認沒有先出現大片空白、再延遲補上區塊的視覺斷裂感。
4. 確認沒有 browser console error。

### 流程 E：375px 響應式驗證

1. 將 viewport 設為 `375px`。
2. 確認共享 route tabs 與路由按鈕群仍可辨識，且沒有水平捲動。
3. 檢查長音規則、清音拗音、合拗音、外來語矩陣：
   - 不得裁切
   - 不得重疊
   - 不得透過水平捲動解決版面不足
4. 若空間變緊，確認調整順序為先縮減內距，再縮小字體。

### 流程 F：Scope ownership

1. 依序檢查 `/grammar` 與 `/vocabulary`。
2. 確認它們沒有出現本 feature 的長音表格、外來語矩陣或新羅馬音版型。
3. 打開既有考題彈窗與錯題面板流程，確認沒有出現本 feature 新增內容。

## 3. 建議驗證指令

```bash
npm run lint
npm run typecheck
npm run test:unit
npm run build
npx playwright test tests/e2e/app-shell.smoke.spec.ts tests/e2e/practice-layout.smoke.spec.ts
```

## 4. PWA / 離線手動確認

1. 執行 `npm run build`。
2. 以既有 PWA 驗證方式開啟站點。
3. 在離線狀態重開 `/practice`。
4. 確認長音規則、拗音與外來語矩陣的新增靜態資料仍可顯示。
