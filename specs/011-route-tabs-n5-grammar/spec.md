## User Scenarios & Testing *(mandatory)*

### User Story 1 - 改善路由切換可讀性 (Priority: P1)

作為在手機與桌面裝置切換學習頁面的使用者，我希望頂部路由切換區塊更清楚、更容易點擊，避免標題佔位與按鈕文字過小或斷行造成辨識困難。

**Why this priority**: 這是所有主要學習流程共用的導航入口，若切換區塊難以辨識，會直接影響整個應用程式的基本使用效率。

**Independent Test**: 只實作此故事時，使用者仍可在現有各主路由之間切換，並驗證標題移除、按鈕靠左、文字不斷行與必要時可自動換列。

**Acceptance Scenarios**:

1. **Given** 使用者進入任何帶有主路由切換按鈕的頁面, **When** 頂部導航區塊載入, **Then** 左側原有標題不應顯示，路由切換按鈕群組應靠左排列。
2. **Given** 使用者在較窄的視窗寬度檢視主路由切換區塊, **When** 單列空間不足以容納全部按鈕, **Then** 按鈕群組可換列顯示，且每顆按鈕內的文字不得在按鈕內部斷行。
3. **Given** 使用者檢視主路由切換按鈕, **When** 與現行版本比較, **Then** 按鈕文字應明顯放大至約現況 1.15 倍，同時維持可點擊與可閱讀性。

---

### User Story 2 - 提升字母練習表格辨識度 (Priority: P2)

作為在字母練習頁面背誦清音與濁音變化的使用者，我希望指定表格中的文字更大，讓我在快速掃視表格時更容易辨識內容。

**Why this priority**: 這是核心學習畫面的局部可用性改善，影響練習效率，但不如全域導航調整來得廣泛。

**Independent Test**: 只實作此故事時，進入字母練習頁面即可驗證清音與濁音／半濁音表格內文字是否放大，且其他未提及區塊保持不變。

**Acceptance Scenarios**:

1. **Given** 使用者進入字母練習頁面, **When** 檢視清音表格與濁音／半濁音表格, **Then** 表格內部文字原則上應放大至約現況 1.1 倍；若該倍率造成破版、裁切或額外斷行，系統可微幅下修至仍明顯大於現況的最小穩定值，且每格中的假名與羅馬音之間必須保有 `4px` 間距。
2. **Given** 使用者進入字母練習頁面, **When** 檢視未被點名的其他區塊, **Then** 它們的版面與內容不應因本次調整而被一併改動。

---

### User Story 3 - 新增 N5 文法入口與占位頁 (Priority: P3)

作為規劃後續學習內容的使用者，我希望先看到新的 N5 文法入口，並在點入後看到清楚的「製作中」占位內容，知道功能正在準備中。

**Why this priority**: 這能提前建立資訊架構與導航位置，但目前僅需占位內容，因此優先順序低於既有導航與練習頁的可用性優化。

**Independent Test**: 只實作此故事時，使用者可在主路由切換區塊找到 `N5文法` 按鈕，點擊後進入獨立路由並看到占位文字。

**Acceptance Scenarios**:

1. **Given** 使用者檢視主路由切換區塊, **When** 查看 `單字練習` 按鈕右側, **Then** 應能看到新的 `N5文法` 按鈕。
2. **Given** 使用者點擊 `N5文法` 按鈕或直接開啟該路由網址, **When** 頁面載入完成, **Then** 應顯示 `製作中` 作為主要內容，且不影響既有 `文法規則` 內容。

### Edge Cases

- 當主路由按鈕數量增加到超過一列時，群組必須可自然換列，且不能要求使用者水平捲動才能看到完整按鈕。
- 當裝置寬度落在 320px 至 375px 的常見手機範圍時，每顆主路由按鈕的文字都必須維持單行完整顯示，不得被截斷或互相重疊。
- 當使用者直接以網址進入新的 N5 文法路由時，系統必須能直接顯示合法占位內容，而不是空白頁、渲染失敗或主控台錯誤。
- 當字母練習頁載入預設狀態時，清音與濁音／半濁音表格的字體放大不得造成儲存格溢出、裁切或破壞既有表格對齊。
- 本功能的範圍僅包含主路由切換區塊、字母練習頁指定表格，以及新的 N5 文法占位路由；既有單字練習、文法規則內容、測驗流程與其他未提及畫面皆維持原狀。
- 若共享按鈕樣式或共享頁首樣式與此需求衝突，必須以此功能的路由切換可讀性規則為優先，但不能把調整外溢到不在範圍內的介面區塊。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須移除現有主路由切換區塊左側標題文字，讓主要可見焦點只保留路由切換按鈕。
- **FR-002**: 系統必須讓主路由切換按鈕群組靠左排列，並在可用寬度不足時改為多列呈現，而不是壓縮成難以辨識的單列。
- **FR-003**: 系統必須讓每顆主路由切換按鈕內的文字維持單行顯示，且文字尺寸需提升至現況約 1.15 倍。
- **FR-004**: 主路由切換區塊的調整只適用於主路由導航本身，不得連帶改動其他未提及的頁首標題、內容文字或非導航按鈕。
- **FR-005**: 在字母練習頁中，系統必須將清音表格與濁音／半濁音表格內部文字原則上放大至現況約 1.1 倍；若該倍率造成破版、裁切或額外斷行，允許微幅下修至仍明顯大於現況的最小穩定值。
- **FR-005A**: 清音表格與濁音／半濁音表格每個儲存格中的假名與羅馬音之間，系統必須維持 `4px` 的垂直間距。
- **FR-006**: 字母練習頁的字級調整不得影響未被明確點名的其他表格、學習區塊或流程行為，除非是為了避免同一表格內發生排版錯位所必需的最小調整。
- **FR-007**: 系統必須新增一個新的主路由項目 `N5文法`，其位置必須緊接在 `單字練習` 之後。
- **FR-008**: 系統必須提供 `N5文法` 對應的獨立路由，並在使用者透過按鈕或直接網址進入時顯示 `製作中` 占位內容。
- **FR-009**: 新的 `N5文法` 路由目前僅為占位入口，不得取代、覆寫或混淆既有 `文法規則` 路由與內容。
- **FR-010**: 本次調整不得影響未被提及的頁面、資料、測驗流程與互動規則。
- **FR-011**: 由於本功能變更了應用程式的路由結構與導航資訊架構，實作時必須同步更新 `PROJECT_ARCHITECTURE.md` 中與路由或模組導覽相關的說明。

### Key Entities *(include if feature involves data)*

- **主路由切換群組**: 應用程式頂部的主要導航區塊，包含按鈕順序、左對齊、多列換行能力，以及每顆按鈕文字必須維持單行顯示的規則。
- **字母練習表格文字區**: 字母練習頁中清音表格與濁音／半濁音表格的可視文字內容，必須放大但仍保持既有表格可讀與對齊。
- **N5 文法占位路由**: 新增的頂層路由入口，包含按鈕標籤、相對位置與最初僅顯示 `製作中` 的占位狀態。

### Assumptions

- 「子路由-字母練習」指的是目前提供日文字母表練習內容的既有主要路由。
- 「現在文字大小的 1.15 倍」與「1.1 倍」以目前正式版本的視覺呈現作為基準，允許因字體與裝置像素取整而有極小誤差；其中 `/practice` 指定表格的 `1.1 倍` 屬目標倍率，若該倍率造成破版、裁切或額外斷行，可微幅下修至仍明顯大於現況的最小穩定值。
- 「放在單字練習按鈕的右側」解讀為主路由切換順序中的緊鄰下一個位置，而非其他區塊中的額外入口。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 375px 寬度下檢視主路由切換區塊時，所有按鈕都能保持靠左排列，且沒有任何按鈕文字在按鈕內部換行。
- **SC-002**: 當主路由按鈕總寬超過單列可容納空間時，使用者仍可在不進行水平捲動的情況下看見並點擊全部按鈕。
- **SC-003**: 在字母練習頁中，清音表格與濁音／半濁音表格的文字相較於目前版本明顯放大，目標約為現況 `1.1x`，且在手機與桌面截圖中均無裁切、重疊、額外斷行或對齊破壞；若需微幅下修，也必須維持明顯大於現況，並保持假名與羅馬音之間固定 `4px` 間距。
- **SC-004**: 使用者能在一次點擊內從主路由切換區塊進入 `N5文法` 頁面，或直接以網址進入，並看到 `製作中` 作為首屏主要內容。
- **SC-005**: 本次功能完成後，未被點名的既有路由與流程在 smoke 驗證中維持既有可用性，沒有新增的渲染錯誤或瀏覽器主控台錯誤。
