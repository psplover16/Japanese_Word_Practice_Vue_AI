# 功能規格：N5 文法新增邀約與變化表現整理

**Feature Branch**: `feature/016-n5-change-invitation`  
**Created**: 2026-04-16  
**Status**: Draft  
**Input**: User description: `@/_private/_private_notes/v15/specify.txt`

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 閱讀邀約表現並分辨語氣差異 (Priority: P1)

作為正在 `/n5-grammar` 學習 N5 文法的使用者，我希望能在同一輪新增內容中讀到 `ませんか` 與 `ましょう` 的整理版說明、語氣差異與例句，這樣我能分辨「禮貌邀請對方一起做」與「較肯定地提議一起做」的不同。

**Why this priority**: `ませんか` 與 `ましょう` 是本輪筆記最直接的學習目標，而且筆記明確提醒兩者要一起比較，若沒有先釐清差異，整體內容就無法成為可用的學習資源。

**Independent Test**: 僅實作邀約表現相關內容時，使用者仍可獨立完成 `ませんか`、`ましょう`、普通體對照與代表例句的閱讀與比較，已具備明確學習價值。

**Acceptance Scenarios**:

1. **Given** 使用者進入 `/n5-grammar`，**When** 展開本次新增的邀約表現區塊，**Then** 能看到 `ませんか` 的用途說明、至少一個來自筆記或依筆記補齊的例句，並理解其偏向詢問對方意願的語氣。
2. **Given** 使用者進入 `/n5-grammar`，**When** 展開本次新增的邀約表現區塊，**Then** 能看到 `ましょう` 的用途說明、至少一個來自筆記或依筆記補齊的例句，並理解其偏向較肯定提議一起做的語氣。
3. **Given** 使用者閱讀邀約表現內容，**When** 查看比較說明，**Then** 能看到 `ませんか` 與 `ましょう` 的差異整理，以及與普通體表達（如 `見ない？`、`帰ろう`）的對照補充。

### User Story 2 - 閱讀自然變化與人為改變的差異 (Priority: P1)

作為正在整理 N5 變化句型的使用者，我希望能清楚讀到 `～くなります / ～になります` 與 `～くします / ～にします` 的結構、詞類接續與差異，這樣我能分辨「自然變成某狀態」與「人為弄成某狀態／決定成某狀態」。

**Why this priority**: 筆記的第 2、3 章是本輪最核心的句型整理內容，也是最容易因資料破碎而混淆的區塊；若不把差異講清楚，使用者很難拿來學習。

**Independent Test**: 僅實作變化表現相關內容時，使用者仍能透過詞類接續整理、語意對比與例句獨立完成學習，不依賴其他新增主題。

**Acceptance Scenarios**:

1. **Given** 使用者閱讀 `～くなります / ～になります`，**When** 查看各詞類接續，**Then** 能分辨 `い形容詞`、`な形容詞` 與名詞在自然變化句型中的接法與意義。
2. **Given** 使用者閱讀 `～くします / ～にします`，**When** 查看各詞類接續，**Then** 能分辨 `い形容詞`、`な形容詞` 與名詞在人為改變或決定句型中的接法與意義。
3. **Given** 使用者閱讀這兩組變化表現，**When** 查看比較內容，**Then** 能看到至少一處明確整理自然變化與人為改變的差異，並搭配對應例句。

### User Story 3 - 在既有 N5 文法頁中穩定閱讀新內容 (Priority: P2)

作為整個學習站點的使用者，我希望本次新增內容只出現在 `/n5-grammar`，並沿用既有可收合卡片與排序規則，這樣我能在熟悉的閱讀方式下看到新文法，而不會影響其他 route 或既有版面。

**Why this priority**: 這次需求屬於既有學習頁的增量整理，最重要的風險是內容外溢、排序錯亂或版面回歸；控制這些風險可避免後續重工。

**Independent Test**: 僅驗證頁面整合與範圍隔離時，也能確認新內容在 `/n5-grammar` 可正常閱讀、排序正確、可收合且不影響其他 route。

**Acceptance Scenarios**:

1. **Given** 使用者進入 `/n5-grammar`，**When** 查看本次新增內容，**Then** 新增主題必須以非助詞內容出現，並維持與來源筆記一致的章節順序。
2. **Given** 使用者在行動裝置寬度閱讀 `/n5-grammar`，**When** 展開本次新增區塊，**Then** 標題、說明、表格或條列內容都必須保持可讀，不得出現明顯破版或重疊。
3. **Given** 使用者切換到 `/practice`、`/grammar` 或 `/vocabulary`，**When** 本次功能完成後，**Then** 不得出現本次新增的 N5 文法內容外溢到其他 route。

---

### Edge Cases

- 若來源筆記有明顯錯字、未完成片段或不自然句型，系統仍需修正為可學習的正確內容，同時保留原本想表達的文法重點。
- 若來源筆記只有零碎提示、沒有足夠完整的解釋或例句，系統必須補足到可獨立學習的程度，而不是直接照抄片段。
- 若來源筆記中的羅馬音只是輸入法或發音備註，系統不得讓它取代日文正文；日文句型、讀音與繁中說明仍應是主要學習內容。
- 若同一概念在不同章節互相參照，例如 `ませんか` 與 `ましょう`、`なります` 與 `します`，系統必須提供明確的比較或交叉說明，避免重複又分散的解釋。
- 若本次新增區塊在初始收合狀態下顯示，使用者仍需能從標題與簡短說明辨識主題，不得出現空白或無法理解的容器。
- 本次功能範圍僅限 `/n5-grammar` 的新增非助詞文法內容；既有助詞內容、`/practice`、`/grammar`、`/vocabulary`、共享 route tabs 與 app shell 都明確不在本次修改範圍內。
- 若 route-specific 的閱讀需求與共用樣式衝突，N5 文法頁的可讀性與既有卡片閱讀結構必須優先。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 將 `v15/note.txt` 中 ch1 到 ch4 提及的所有文法重點整理進 `/n5-grammar`，包含 `ませんか`、`ましょう`、`～くなります / ～になります`、`～くします / ～にします`，不得遺漏。
- **FR-002**: System MUST 將本次新增內容視為非助詞文法，並讓其在 `/n5-grammar` 的非助詞內容區依來源筆記順序排列為 ch1 → ch2 → ch3 → ch4；新內容預設接在既有非助詞內容之後，且整體仍排在助詞群組之前。
- **FR-002A**: System MUST 讓 ch1、ch2、ch3、ch4 各自保有可獨立辨識的學習區塊；即使有跨章節比較，也不得把來源章節完全合併到失去獨立可讀性。
- **FR-003**: System MUST 為每一組文法提供清楚說明與例句；說明需足以獨立學習，例句需優先沿用來源筆記已有例句，若不足再補充新例句。
- **FR-004**: System MUST 修正來源筆記中的明顯錯字、不完整片段與不自然用法，使最終內容成為正確、可閱讀、可學習的 N5 文法資料。
- **FR-005**: System MUST 將相同或相近概念整理成讀者容易比較的結構，至少要明確呈現 `ませんか` vs `ましょう` 的語氣差異，以及 `～く/に なります` vs `～く/に します` 的語意差異。
- **FR-006**: System MUST 讓每個新增區塊都附有標題與分開顯示的說明文字；標題不得夾帶整段說明，並需保留既有可收合／展開的閱讀方式。
- **FR-007**: System MUST 針對每組文法選擇最能幫助快速理解的版型，例如差異重點適合並列比較、規則重點適合條列說明；若採用非既有常見模式，規格與後續計畫必須說明理由。
- **FR-008**: System MUST 將來源筆記中的羅馬音備註視為輔助資訊；若其用途只是輸入法或發音提示，不得取代日文正文、讀音與繁中說明。
- **FR-009**: System MUST 統一專有名詞、詞類稱呼與相關表記，與現有 `變化規則` 與 `/n5-grammar` 既有內容保持一致。
- **FR-010**: System MUST 只在 `/n5-grammar` 顯示本次新增內容，不得把本輪新增的文法內容帶到 `/practice`、`/grammar`、`/vocabulary` 或其他未指定區域。
- **FR-011**: System MUST 在初始渲染、收合狀態與展開閱讀流程中避免空白容器、渲染失敗與明顯瀏覽器錯誤，並在手機常見寬度下維持可讀性。
- **FR-012**: System MUST 在功能若實際改變 repository 結構、模組邊界、共用元件責任、測試結構或路由結構時同步更新 `PROJECT_ARCHITECTURE.md`；若沒有這些結構變更，則不得為本功能額外改寫架構文件。

### Key Entities *(include if feature involves data)*

- **N5 文法區塊**: `/n5-grammar` 中新增的學習容器，用來承載單一章節或單一組文法的標題、說明、內文與例句。
- **文法主題**: 區塊內的具體學習單元，負責描述某一條文法規則、語氣差異、詞類接續或比較重點。
- **例句項目**: 輔助學習的展示資料，每筆至少包含日文句子、必要讀音與繁體中文翻譯，並能區分是來自來源筆記還是後補內容。
- **來源覆蓋紀錄**: 用來追蹤來源筆記各章節與頁面內容的對應關係，確保 ch1 到 ch4 沒有遺漏。

### Assumptions

- 本次以「四個章節皆獨立可閱讀，但相近概念要有跨章節比較」作為預設整理方式，避免為了硬性合併主題而破壞來源筆記的順序。
- 本次新增內容預設接在現有三個非助詞 core 區塊之後，再進入既有助詞群組，以降低既有學習流程被打斷的風險。
- 來源筆記中已有可用例句時，優先沿用並校正；若例句不足、錯誤或只剩片段，則補充新的 N5 程度例句。
- `見ない？`、`帰ろう` 等普通體對照會作為補充比較資訊，用來幫助理解，不代表本次功能要完整擴寫普通體教學。
- `10時になります`、`会議は火曜日にします` 這類表現視為本輪文法整理的一部分，需被納入對應說明或例句中，而不是當作可忽略的零散補充。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `v15/note.txt` ch1 到 ch4 提及的文法事項在 `/n5-grammar` 的覆蓋率達到 100%，沒有遺漏章節或主要句型。
- **SC-002**: 本次新增的每一組文法內容都至少有 1 段可獨立閱讀的說明與 1 個完整例句，讓使用者不需回頭查原始筆記也能理解。
- **SC-003**: 使用者在 `/n5-grammar` 中能明確看到 `ませんか` vs `ましょう` 與 `なります` vs `します` 兩組差異整理，各至少有 1 處並列比較或等效的差異說明。
- **SC-004**: 在 375px 寬度裝置上，本次新增區塊展開後仍可閱讀標題、說明與主要內容，無明顯重疊、截斷到無法理解或水平溢出。
- **SC-005**: `/practice`、`/grammar`、`/vocabulary` 與既有助詞內容的顯示與互動行為維持不變，沒有因本次新增文法而產生內容外溢或版面回歸。
