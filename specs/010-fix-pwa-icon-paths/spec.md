# Feature Specification: 修正網站與 PWA 圖示資產位置

**Feature Branch**: `[010-fix-pwa-icon-paths]`  
**Created**: 2026-04-03  
**Status**: Draft  
**Input**: User description: "bug修正：將一般 icon 與 PWA icon 複製到專案通用的正確位置"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 正確顯示網站圖示 (Priority: P1)

作為開啟日文學習網站的使用者，我希望瀏覽器分頁能立即顯示正確的網站圖示，避免看到遺失圖示或預設圖示，讓網站在首次載入時看起來完整可信。

**Why this priority**: 首次載入的網站圖示是所有使用者都會遇到的入口體驗，若圖示遺失會直接暴露部署問題。

**Independent Test**: 只要啟動應用程式並開啟首頁，就能獨立確認網站圖示是否被瀏覽器成功載入且沒有缺檔。

**Acceptance Scenarios**:

1. **Given** 使用者首次開啟網站首頁，**When** 瀏覽器載入入口頁面，**Then** 分頁應顯示專案指定的網站圖示而不是缺圖或預設圖示
2. **Given** 網站部署在子路徑環境，**When** 使用者開啟對應網址，**Then** 網站圖示仍應從可公開存取的位置正確載入

---

### User Story 2 - 正確提供安裝用圖示 (Priority: P2)

作為想把網站加入主畫面或安裝成 PWA 的使用者，我希望系統提供完整且可解析的安裝圖示，讓裝置能顯示正確的 App 圖示。

**Why this priority**: PWA 圖示是安裝流程與主畫面呈現的必要資產，缺漏會讓安裝體驗失敗或品質下降。

**Independent Test**: 檢查安裝資訊所宣告的圖示是否都能成功取得，即可獨立驗證這項價值。

**Acceptance Scenarios**:

1. **Given** 瀏覽器讀取應用程式的安裝資訊，**When** 系統提供安裝用圖示清單，**Then** 所有必要尺寸的圖示都應可成功存取
2. **Given** 使用者將網站加入主畫面，**When** 裝置建立捷徑或應用程式入口，**Then** 應顯示專案指定的圖示而非空白或錯誤圖示

---

### User Story 3 - 穩定完成部署驗證 (Priority: P3)

作為維護者，我希望專案把網站圖示與 PWA 圖示放在一致且通用的位置，讓開發、建置與部署後都能用相同方式驗證資產，不必額外手動調整。

**Why this priority**: 這能降低後續維護成本，並避免 staging 與 production 因資產位置不一致而出現環境差異。

**Independent Test**: 在本機與部署環境各檢查一次圖示載入結果，即可驗證是否達到一致的維護流程。

**Acceptance Scenarios**:

1. **Given** 維護者完成一次建置或部署，**When** 檢查網站圖示與安裝圖示的公開位置，**Then** 應能在不手動搬移檔案的前提下完成驗證

---

### Edge Cases

- 當網站部署在根路徑以外的位置時，網站圖示與安裝圖示仍需可被正確取得
- 當只有部分圖示存在時，系統必須能在發佈前明確暴露缺漏，而不是讓使用者在執行期才遇到缺圖
- 當瀏覽器首次載入入口頁面時，不可因圖示資產遺失而產生額外的載入錯誤或主控台錯誤
- 本功能只涵蓋網站圖示與 PWA 安裝圖示的公開位置與可用性，不包含重新設計圖示內容，也不包含其他練習、文法或測驗畫面的視覺調整
- 若圖示檔案需要同時服務一般網站入口與安裝流程，系統必須維持一致的資產來源，避免不同入口顯示不一致的品牌圖像

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須在網站入口可直接取得的公開位置提供網站圖示，讓瀏覽器在首次載入頁面時能成功顯示正確圖示
- **FR-002**: 系統必須提供 PWA 安裝流程所需的全部必要圖示尺寸，且每一個宣告的圖示都能被公開存取
- **FR-003**: 系統必須確保網站圖示與 PWA 圖示在根路徑部署與子路徑部署下都能維持有效連結
- **FR-004**: 系統必須讓網站入口圖示與 PWA 安裝圖示使用同一套受維護的正式資產，避免發生不同入口顯示不同圖示的情況
- **FR-005**: 系統必須在發佈前提供可驗證的檢查方式，以便維護者能確認所有必要圖示都存在且可被載入
- **FR-006**: 本功能的影響範圍必須限制在網站入口圖示、PWA 安裝圖示與其公開資產位置，不得連帶改動日文字詞練習、文法表格、測驗流程或其他非圖示功能
- **FR-007**: 本功能因新增根目錄 `public/` 作為正式公開資產位置，必須同步更新 `PROJECT_ARCHITECTURE.md`

### Key Entities *(include if feature involves data)*

- **網站圖示資產**: 顯示於瀏覽器分頁、書籤或網站入口的代表性圖示
- **PWA 安裝圖示組**: 提供給裝置建立捷徑、安裝入口或主畫面使用的多尺寸圖示集合
- **公開資產位置**: 使用者與瀏覽器可直接取得圖示檔案的位置，需在不同部署環境下保持一致可用

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 的首頁首次載入檢查都能成功取得網站圖示，且不出現缺圖請求
- **SC-002**: 100% 的 PWA 安裝圖示宣告項目都能在驗證時成功載入，不出現遺失檔案
- **SC-003**: 維護者能在 2 分鐘內完成網站圖示與 PWA 圖示的公開位置驗證，不需要手動搬移或補放檔案
- **SC-004**: staging 與 production 兩種部署模式下，網站圖示與 PWA 圖示都能維持一致顯示結果

## Assumptions

- 本次需求不要求重新繪製或更換圖示內容，只要求把既有正式圖示放到正確的公開位置
- 專案現有的部署流程會持續支援根路徑與子路徑兩種網址型態
- 圖示驗證會沿用專案既有的建置、測試或人工檢查流程，不另行新增獨立後台功能

## Repository Hygiene *(mandatory)*

- 已確認 repository 內存在 `.gitignore` 檔案
- 本功能不得提交 `node_modules/`
- 本功能不得提交可重新產生的輸出物，例如 `build/`、`dist/` 或 `coverage/`
- 本功能會新增根目錄 `public/` 作為正式公開資產位置，因此必須同步更新 `PROJECT_ARCHITECTURE.md`
